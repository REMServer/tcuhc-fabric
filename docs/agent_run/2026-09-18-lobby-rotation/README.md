# 四座出生大厅与 regen 轮换

在已有 Iceland 大厅和敌人指南针版本上，加入用户提供的 The Valley、SakAuthLobby（带跑酷）、IC WaitingLobby 三座建筑。
使用方式、来源和模板落点见 [大厅轮换说明](../../lobby-rotation.md)。

## 实现

- 三个 schematic 转为 Minecraft 1.21.1 原生 NBT；不增加运行依赖，也不导入附带世界和服务端设置。
- `LobbyDefinition` 集中维护四图顺序、名称和三处安全地板坐标。
- `SpawnPlatform` 按当前大厅选择模板，以各自尺寸保护/清理建筑，以各自地板高度判断跌落；沿用装饰去重机制。
- `UhcWorldData.lobbyTemplate` 固定当前世界的选择；没有记录时读取轮换记录，最后回退到目录第一项。
- `LobbyRotation` 用世界目录旁的持久化文件记录当前及待切换大厅；采用临时文件替换，重生成时不会删除该文件。
- 只有第二次 `/uhc regen` 确认才准备切换；助手启动/标记删除失败撤销待切换状态；启动时根据 `preload` 和 `pregenerating` 两个保留标记是否缺失消耗或撤销请求。
- 已消耗请求的重复启动不会再递增；普通重启、赛后重建和切换已有世界不触发轮换。
- 更新 README、中英文命令说明、Iceland 文档及独立功能说明，配置书页数保持不变。

## 开发服崩溃与恢复（17:15 后）

17:15:03 开发服在玩家交互时因 `NoClassDefFoundError: me/fallenbreath/tcuhc/util/PlayerItems` 退出。原因是在 `runServer` 仍从 `build/classes` 读取代码时执行了 `clean build`，导致延迟加载的类暂时消失。17:15:07 日志确认所有维度保存完成。此问题由本次在线构建操作引入，与客户端网络无关。

- 先复制保存后的完整世界到忽略目录 `run/server-recovery/world-before-recovery/`（约 61 MiB），保留当前 SakAuthLobby、世界元数据和已生成地形。
- 预生成新增 `pregenerating` 标记：开始前写入，完成并成功写入 `preload` 后删除。普通启动保留该标记的世界并重新扫描、补齐区块；显式 regen 删除两个标记后仍按原语义重建和轮换。
- 当前旧世界在崩溃前尚无此恢复标记，备份后为它补入标记，再以新代码启动；不伪造 `preload`，不把未完成的预生成当成已完成。
- 本机启动脚本已改用 `run/start-frozen-server.py`：从 `run/server-runtime/current.txt` 指定的独立副本启动。编译类、资源、依赖 JAR、映射和启动配置均复制到该副本，不再在线读取 `build/`。
- 冻结副本只含生产入口，包含地狱门和耕地保护，不含临时测试类。后续源码编译不会自动更新运行副本；部署新版必须先生成新的完整副本并在重启时切换，不能修改正在运行的副本。
- `run/start-dev-server.sh` 与原 regen 重启助手仍是入口，所以普通启动和 regen 都使用冻结副本；机器专属路径和文件不提交。
