# 当前附魔书生成逻辑

以下为 1.21.1 奖励箱附魔书优化后的规则（2026-09-16）。本次范围为本模组奖励箱，村民交易、附魔台和已经生成的物品不受本次修改影响。

## 地图奖励箱

实际注册入口是 `UhcFeatures.BONUS_CHEST` → `BonusChestFeature`。区块生成阶段安排放置，区块就绪后在服务端 tick 中填充箱子，不调用奖励箱 JSON 战利品表。

生成箱子的条件由地形位置、群系基础概率和 `chestFrequency` 共同决定，`trappedChestFrequency` 决定其中多少为空箱。例如后者设为 `0.2` 时，约 20% 的生成箱子走空箱逻辑，空箱不会生成附魔书。

非空箱先放普通物品，再按原来的顺序抽取其他珍贵物品；附魔书独立抽取，最后放入随机空槽位。其他珍贵物品先抽中不会阻止出书，书也不会覆盖已经放入的物品。

| 战斗类型 | 附魔书独立抽取结果 | 每个非空奖励箱的概率 |
| --- | --- | --- |
| 所有类型 | 从该战斗类型的池中生成随机书 | 4/64 = 6.25% |
| 仅海战 | 固定引雷 I 书 | 1/64 = 1.5625% |
| 仅海战 | 固定激流 I 书 | 1/64 = 1.5625% |

上述结果来自一次 64 等分的互斥抽取，每箱最多一本书。普通和 ICARUS 非空箱总出书率为 6.25%，海战为 9.375%；空箱仍然不出书。

旧逻辑把随机书排在钻石等物品之后，实际约 4.67% 才能出随机书。现在概率直接由独立抽取决定，不再受到这些物品的顺序影响。书从原珍贵物品池移除后，也不再阻挡排在它后面的非书奖励。

## 随机书的附魔与等级

每本随机书仅有一个附魔，从对应战斗类型的池中等概率选择：

| 战斗类型 | 附魔池 |
| --- | --- |
| 普通 | 力量、锋利、火焰附加、保护、弹射物保护 |
| 海战 | 普通池加忠诚、激流、穿刺、冰霜行者、水下速掘、深海探索者 |
| 鞘翅战斗类型（ICARUS） | 普通池加摔落缓冲 |

效率已从三个池中移除，耐久原本不在这些池中。当前所有奖励箱出书路径都只使用这些池或上述两个海战特殊项。

等级仍以 75% I、25% II 抽取，再限制在对应附魔的合法等级范围内；例如水下速掘只有 I，因此不会再生成水下速掘 II。

当前没有可配置的附魔书专用概率、种类或等级选项。`chestItemFrequency` 虽在配置中存在，但当前奖励箱填充路径未读取它；增加这个选项不能直接提高这里的附魔书概率。

对应修改位置：`BonusChestFeature.createBonusBook` 控制独立出书概率，三个 `*_ENCHANTMENTS` 数组控制种类，`createEnchantedBook` 控制随机等级，`createSpecificEnchantedBook` 限制合法等级，`placeBookInEmptySlot` 避免覆盖已有奖励。

新规则只对使用新版代码填充的新奖励箱生效。重启不会清空已生成的箱子或删除玩家已有的书。

## 其他代码路径

- 原版村民附魔书交易由 `TradeOffersEnchantBookFactoryMixin` 将每个交易的最大使用次数改为 1；该 Mixin 不修改附魔类型、等级或价格。
- `loot_tables/` 中还有结构箱和旧奖励箱 JSON，其中 `enchant_with_levels` 使用附魔能力等级生成书，不等于 I/II 等附魔等级。它们不是上述 `BonusChestFeature` 的填箱来源；本次未对所有结构箱逐个做运行验证。
- 旧 `BonusChestGenerator` 使用奖励箱 JSON，但当前 `TcUhcMod` 没有注册这个生成器。

## 验证

2026-09-16 在独立 Fabric 1.21.1 专用测试服通过 24 项检查：穷举各模式的 64 种出书抽取结果，每模式随机生成 4000 本书检查附魔池和等级，并对 256 个种子实际生成奖励箱。覆盖效率和耐久排除、每箱最多一本、与珍贵物品共存、空箱不出书、满箱不覆盖以及水下速掘等级上限。测试入口和日志保存在忽略目录 `run/sidebar-smoke/`，不加入发布构建。
