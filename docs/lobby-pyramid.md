# 金字塔出生大厅（Minecraft 1.21.1）

这是首次 NBT 大厅试验的记录。当前使用的大厅已改为 [Iceland](lobby-iceland.md)，
金字塔模板仍保留在资源目录中。

大厅由结构模板 `tcuhc:lobby/pyramid` 放置，资源文件为
`src/main/resources/data/tcuhc/structure/lobby/pyramid.nbt`。

## 模板内容

- 尺寸：21 × 10 × 21（X、Y、Z），底层是完整的石砖广场，四周有铁栏杆。
- 中央建筑来自仓库的 `ender_pyramid/main.nbt`，在新模板内偏移 (4, 1, 4)。
- 保留石砖、楼梯、黑曜石和旗帜；岩浆替换成海晶灯，虫蚀方块替换成普通方块。
- 移除末影水晶、奖励箱和结构标记。原有自然生成金字塔模板不受影响。
- 模板含完整空气区域，重复放置时会恢复大厅内部空间。

## 代码与坐标约定

`SpawnPlatform.generatePlatform()` 通过 `StructureTemplateManager` 加载 NBT，
将模板水平居中在主世界 (0, 0)，并沿用地形采样及世界 `uhc.json` 中的平台高度。
高度会限制在可完整容纳模板的范围内。

出生点是模板内的地板坐标 (8, 0, 2)、(10, 0, 2)、(12, 0, 2)，
玩家脚部在地板上方 1.1 格，朝向南侧的金字塔。生成时检查地板和两格头部空间。
替换建筑时需同时维护这些落点。

开局按模板完整包围盒清除大厅；赛后先重建模板再将玩家传送回主世界。
配置阶段只补齐地板空洞，不再生成旧大厅的大范围屏障围墙。

## 本地开发

使用 JDK 21，在基于 `1.21.1` 的分支运行 `bash gradlew runServer`。
开发服文件位于忽略的 `run/` 目录。修改 Java 或 NBT 后停服，再启动开发服。
单独测试模板可在创造模式空旷位置使用：

```mcfunction
/place template tcuhc:lobby/pyramid 100 200 100
```

验证出生大厅时检查：首次加入、重新连接、掉落返回、跨维度返回、
开局完整清理，以及对局结束后 `/uhc config` 重建大厅。
单纯调整大厅不需要 `/uhc regen`。
